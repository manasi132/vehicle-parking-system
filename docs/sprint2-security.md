# Sprint 2 security verification

- Automated API coverage includes wrong-role 403 responses and production-configuration 429 throttling for authentication and reservation requests. The booking limiter is per process and per IP; shared or multi-instance deployments need a shared rate-limit store and trusted-proxy configuration.
- `npm audit --omit=dev` reported no production dependency vulnerabilities for backend or frontend in this local run. This does not cover development-only dependencies or replace a security assessment.
- **OWASP ZAP 2.17.0 passive baseline: completed locally.** The final report is saved as `docs/security/zap-baseline-local.json`. It contains one informational finding, “Modern Web Application,” and no high, medium or low findings. The initial local frontend preview lacked CSP, anti-clickjacking and content-type headers; preview and reverse-proxy configuration were updated and the passive scan rerun. A real Stripe Elements test-mode browser payment and refund subsequently passed through the preview CSP. This scan covered a disposable loopback frontend and unauthenticated GET responses from selected API routes; it did not cover authenticated flows, active attacks, or a deployed server.
- Reproduce the local passive scan after building the frontend with `ZAP_HOME` and `ZAP_DATA_DIR` pointing to a local ZAP 2.17.0 installation and add-ons, and `ZAP_JAVA` pointing to a compatible Java executable: `node backend/scripts/run-zap-baseline-local.cjs`. It starts disposable loopback services and does not use Stripe or shared credentials. The preview headers support a configured API origin; a separate deployed frontend host must configure equivalent headers, including the actual HTTPS API origin in CSP `connect-src`.
- The public availability stream exposes only lot ID, slot ID, status and timestamp; it does not broadcast reservation or vehicle details. Its event source is an in-process emitter, so a multi-worker deployment still requires shared fan-out.
- Manasi's open OTP delivery hardening branch must be integrated and its provider configured; the development OTP adapter here is a logging stub. Review admin-write audit atomicity and booking lease-expiry/crash behavior before production use.
